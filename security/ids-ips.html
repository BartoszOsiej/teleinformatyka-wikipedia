IDS & IPS

Intrusion Detection System and Intrusion Prevention System — monitoring network traffic for malicious activity.

IDS vs IPS​

FeatureIDSIPS
ModePassive (monitor only)Active (blocks threats)
PlacementOut-of-band (tap/mirror)Inline (in traffic path)
ActionAlert onlyAlert + block
ImpactNo network impactCan cause latency
RiskNone (watch only)Can block legitimate traffic

Detection Methods​

MethodDescriptionPros/Cons
Signature-basedMatch known attack patternsFast, no false positives for known attacks, misses new attacks
Anomaly-basedDetect deviations from baselineCatches new attacks, higher false positive rate
Stateful protocolUnderstand protocol behaviorAccurate for known protocols
HeuristicUses rules/algorithmsCatches variants of known attacks

Signature Types​

TypeDescription
Text stringsMatch specific byte sequences
Regular expressionsPattern matching
Context signaturesConsider packet position/state
CompositeCombine multiple conditions

IPS Deployment​

Internet ──► [Firewall] ──► [IPS] ──► [Switch] ──► LAN
                        (inline)    (bypass if IPS fails)

Inline vs Tap​

ModeDescription
InlineTraffic passes through IPS (can block)
Tap/SPANCopy of traffic only (detection only)
BypassIPS fails open (traffic continues)

Snort Rule Example​

# Alert on SQL injection attempt
alert http $EXTERNAL_NET any -> $HTTP_SERVERS any \
  (msg:"SQL Injection attempt"; \
   content:"SELECT"; nocase; \
   content:"FROM"; nocase; \
   sid:1000001; rev:1;)

# Alert on port scan
alert tcp $EXTERNAL_NET any -> $HOME_NET any \
  (flags:S; threshold:type both, track by_src, count 20, seconds 60; \
   msg:"Port scan detected"; sid:1000002; rev:1;)

False Positives​

CauseMitigation
Legitimate traffic patternsTune signatures
Encrypted trafficSSL inspection
New applicationsUpdate baselines
Misconfigured rulesRegular rule review
